# AI 资讯 → 单篇热点文章 → 公众号草稿

本技能目录记为 `SKILL_DIR`（就是本文件所在目录）。所有路径相对 `SKILL_DIR`。

## 执行步骤

1. **抓新闻**：`node scripts/fetch_news.mjs`，然后读 `scripts/digest.md`。
   个别源失败属于正常，忽略失败的源继续；如果所有源都失败，向触发渠道报告失败原因，不要硬写。

2. **定选题与角度**：从摘要里挑出**今天最热的一条**新闻，它是本文唯一主角：
   - 热度信号：多个源同时在报、HN 高分高评论、有官方公告或多方回应、读者会转发讨论的那种。
   - **热度五维**（选题时在心里过一遍，别只看 HN 分数）：平台热度（同时热在几个平台）、
     互动热度（评论/点赞/转发量）、趋势热度（正在涨 vs 已经凉）、内容质量（标题与信息密度）、
     爆款潜力（情绪价值 + 传播动力）。
   - **官方发布源优先扫**：候选来源先看官方发布条目（OpenAI / Anthropic / Google / DeepSeek / 通义 /
     字节等官方博客或模型发布 RSS）——新模型、新技术、新突破通常先出现在这里；别只从资讯站的「热门」里挑。
   - **外行可懂性门槛**（只过滤纯论文细节，不牺牲模型/技术新闻）：判断标准是「能不能讲清它改变了什么、
     跟读者有什么关系」——技术抽象不等于不可懂，新模型/新技术要用「它带来的变化」讲，而不是用参数和
     架构术语讲。只有纯论文细节（形式化验证、逐项跑分表）才跳过。
   - 优先在**热题上找差异化角度**；「换次热题」是找不到角度时的次选，不是首选——热题的总读者池远大于次热题。
   - 类型范围按账号定位（见文末）：**以 AI 新闻为主线**——新模型/重大版本发布、产品与开源生态更新、
     技术或科研突破、AI 落地应用/提效。
   - **类型配比（硬要求）**：每 5 期里**至少 3 期**是「模型/产品发布」或「技术/科研突破」类；
     应用、商业、政策类合计最多 2 期，且应用/商业类**不能连续两期**。连写两期应用/商业，第三期强制换
     模型或技术题——模型和技术是账号的专业感与差异化来源，别把号做成「AI 应用观察」。
     **配比自查**：选题前先 `node scripts/topic_log.mjs --tail 5` 看最近 5 期的类型，本期按上面的比例决定；
     定稿后记录：`node scripts/topic_log.mjs --type <模型|产品|技术|应用|商业|政策> --title "本期标题"`。
   - **国内大厂 AI 商业战局（次选，硬配额）**：财报、融资、估值、烧钱、利润、亏损、租约、订单、股价。
     硬规则（三条同时满足才允许选，否则一律换题）：
     - 当天摘要里**没有任何**新模型 / 产品功能 / 技术突破 / 落地应用类条目；
     - 每 5 期最多 1 期资金/财报类，且不能与上一期同类；
     - 自检：「这条是『AI 发生了什么』，还是『AI 公司赚了多少钱』？」——后者换题。
     写法抓反差（越成功越焦虑、越亏越下注）是笔法，不能当作选题理由。
   - **差异化硬门槛**（跟全网 AI 号撞车的解法，每期必过）：
     - 列 2~3 个候选主角，逐个自问：「今晚其他 AI 号大概率会怎么写它？」——它们都会写的角度就是禁区。
     - **模型/技术类热点例外**：这类新闻读者需要第一时间知道，热度权重高于角度——即使角度不如别人尖锐
       也要覆盖（同题材必写，角度求稳不求奇）。「拿不到角度就换次热、跟读者的钱/时间/饭碗相关的题」
       只适用于应用/商业类热点。
     - 类型别扎堆：**同一个模型/同一家公司连出两期后**，下一期换别的模型或技术新闻（不是被迫换应用）；
       应用/商业类不能连续两期。
     - 角度必须从下面挑一个，不从「事件本身」出发：
       ① 算一笔别人没算的账（成本/时间/风险）；② 谁受益谁受伤；③ 上手实测（别人转述，我们动手）；
       ④ 反共识判断（都说好我挑毛病，都在慌我说不慌）；⑤ 中文语境翻译（这事对国内读者到底意味着什么）；
       ⑥ 故事叙事（把一个具体的人/团队的真实经历讲成小故事，先有人再有观点）；⑦ 情感共鸣（让读者觉得「说的就是我」）。
   - 定了主角后，围绕它用 web_search 补素材：官方公告、技术细节、各方反应、相关数据（全文最多搜 5 次，当前走 Tavily）。
     **搜索额度自愈**：web_search 若报额度类错误（429 / usage limit / quota exceeded），执行
     `openclaw config set tools.web.search.provider brave` 切到 Brave 并重试；平时不要动这个配置。
   - 事实必须可溯源，禁止编造摘要和搜索结果里没有的数字、引语。
   - 当天没有特别突出的热点时，选信息量最大的一条深挖，**不要写成多闻合辑**。

3. **写作**（中文，每篇 1000~3000 字——按骨架分档见参考结构；少于 1000 字信息量不够，超过 3000 字
   移动端完读率会崩。目标：**一篇有自己观点的单篇评论文章，像真人编辑写的，不是通稿复述**）：
   - 标题 ≤ 45 字（双句转折式可写满；单句尽量 ≤ 30），目标：**读者在信息流里划过去 1 秒就想点**。
     **禁圈内黑话**：权重、token、跑分、架构名、杯型体系这类只有圈内人懂的词不能出现在标题里；
     每个词都过一遍「不搞技术的人能不能看懂」，看不懂就翻译成利益（钱/时间/工作）。
     实体打底（点清主角是谁）+ 钩子加码，钩子从下面挑 1~2 个组合，不贪多：
     ① 对抗冲突：确有对比数据时敢点名对手（「绝杀OpenAI」）；
     ② 拟人场景：把模型当人写（「上岗」「替你打工」「抢饭碗」）；
     ③ 具体数字：价格/时长/倍数（「24小时」「一个任务一块五」），好过「价格再创新低」；
     ④ 利益代入：直接写跟读者的关系（「替你」）；
     ⑤ 强转折骨相（大厂商业类首选）：两句对照各带一个具体数字——投入大却失灵、增长猛却藏转型、
       越成功越焦虑、越亏越下注；公司可以当人写命运（「慌了」「渡劫」「下注」）。
     金额数字必须配参照系（「一季度赚 330 亿，秒了整个科创板一年的利润」），光秃秃的金额不如有对比的金额。
     正文写完后**强制产出 3 个不同钩子的候选标题**自比，选信息流里最想点的那个；
     允许最多一个感叹号，只放在钩子处，不连用标点。
     吸睛的底线是事实：不编造排行宣称、金额、时间词、权威背书；「绝杀/吊打」级强度词必须有真实对比
     数据撑腰，撑不住就降级为可证实的说法。
   - **先判题材，再套骨架**（别每篇一个模子；连续两期不重复用同一骨架）：
     共同约束：正文编号小节（01 起，样式见第 5 步）、每节只回答一个问题、小节标题写利益点、
     结尾不编号、开场不写通稿式「X月X日，Y发布了Z」、第一句不进「先说结论」总起。
     **字数硬线：全篇 1000~3000 字，各骨架分档如下，check_style 会查。**

     ① **发布/评测型**（新模型、新产品、新功能发布 · **1000~1500 字**）：
        用具体场景或演示细节开场 → 01 它是什么/核心卖点 → 02 价格或性价比 → 03 上手或第三方验证
        → 04 争议（有则加） → 收尾：谁该用·谁不该用的清单式。要快、要利落。

     ② **翻车/争议型**（道歉、召回、事故、舆论风波 · **1000~1500 字**）：
        直接上最刺眼的事实或数字开场 → 01 到底发生了什么（时间线） → 02 谁的错/根因
        → 03 影响多大 → 04 官方回应 vs 社区质疑 → 收尾：一句话事实戛然而止。

     ③ **商业/战略型**（财报、烧钱、战略转向 · **1200~2200 字**，算账和论证需要篇幅）：
        一个反常数字 + 参照系开场 → 01 算账 → 02 反差背后的逻辑 → 03 谁受益谁受伤
        → 04 风险/反方（有则加） → 收尾：金句判断单独成段。

     ④ **观点/评论型**（趋势判断、无硬新闻的解读 · **1500~2500 字**，论证需要铺开）：
        先亮一句反共识判断开场 → 01 论证 → 02 承认边界 → 03 反方 → 收尾：金句收束 + 争论问题。

   - **「反方」规则（所有骨架通用）**：有实质素材才加，宁缺毋滥，放在结论前、正常占编号；写缺点、质疑、
     社区吐槽或对手更强的数据，引原话挂来源。注意「反方」只是编辑功能名，**不要出现在读者看到的标题里**——
     小节标题照常按利益点/判断式写（如「它就是个中档货」「谁在慌」）。动笔前先找真实反方素材，
     找不到有来源的实质素材就不要硬凑，为反而反同样伤可信度。
   - **收尾规则（按骨架）**：①②③ 不硬加争论问题；④ 才以争论问题收尾。「我的判断」若写成金句，
     单独成段、前后留白（一两句、值得截图转发）。三种收尾（金句 / 清单 / 一句话事实）随骨架走，别每期一样。
   - **借来的好手艺**（研究量子位/TLDR/The Rundown 后的结论）：
     - 事实段三句式：是什么 → 核心数据/对比 → 价格与获取渠道，能三句说完不写五句。
     - 断言挂信源：厂商的宣称写「官方称/其表示」，自己的判断才用「我」——两类声音必须分开，这是可信度的来源。
     - 关键段结尾带一句「这意味着什么」：不停留在转述，用一句话点出赌注或待验证的问题。
     - 「怎么用」给具体动作：入口、命令、prompt、价格，读者能直接复制照做。
     - 对「颠覆/史诗级/一夜变天」式宣称保持警惕：先查证据，多数真正的变化比宣传小一号。
     - 评论的底气来自动手：有条件就实测（跑一个最小例子、查官方文档），没条件就明说依据，**不装亲测**——「我先做过了，所以不必喊」。
     - 人味来自判断、节奏和具体细节，**不靠编造个人经历或生活场景**（AI 没有生活，编了就是假新闻）。
   - **要有「自己的东西」**：观点、判断、延伸、类比、算一笔账都可以；把几段通稿拼起来不算写完。
   - **互动设计（每篇必做，目标：看完、留言、转发各占一个钩子）**：
     - 结尾抛一个**具体的、可站队的争论问题**，禁止「你怎么看」这种空问；要问「你的邮箱敢交给它管吗」
       「这个价你会换吗」这种一句话能答、且答案明显分两派的。
     - 争议点在文中要有正反两方，只写一方的文章没人留言。
     - 全文 1~2 句敢下判断的结论句（与风格配额一致，不是每段都有），写到值得截图转发的程度。转发测试：读者转出去是在向同行表达什么
       （「我比同行先知道」/「我看得更准」/「我早说过」）？给不出这句话，就回去把判断写锋利再收尾。
   - **数字可视化（仅在必要时，不是每篇都要）**：当某段数字密集（≥3 个同维度数字、或量级差悬殊的对比）时，
     优先用 `python3 scripts/gen_chart.py --data '<JSON>'` 生成数据图（正文只留结论，图内自动带「数据来源」标注）；
     图表脚本不可用时退回表格或 CSS 条形图（见第 5 步模板）。
     散落的一两个数字直接写在句子里就好，别硬画。数据必须与来源一致，不得为视觉效果歪曲比例。
   - **去 AI 味硬规则**（初稿就要遵守，别指望事后补救）：
     - 禁用词：随着、值得注意的是、总而言之、综上所述、赋能、闭环、助力、不仅…更是、在这个…的时代、引人注目、让我们、可以说、毫无疑问、拭目以待、未来已来。
     - 不用「首先/其次/最后」「一方面/另一方面」的机械结构；不用三句式排比堆砌。
     - 长短句交错，一段不超过三句，多用短句；开头一句直接说事，不铺垫宏大背景。
     - 点评要有具体立场，敢下判断；引用具体数字和细节，不写放之四海皆准的空话。
     - 像编辑跟读者聊天：可以少量用口语衔接（如「这事」「说白了」「好消息是」），全篇不超过 5 处。
     - **风格配额（第 4 步 check_style.mjs 会硬查，超标必须改）**：
       - 对仗/排比（「不是X，是Y」「一边…一边…」「对谁…对谁…」）全篇 ≤ 2 处；
       - 比喻全篇 ≤ 2 个——一个核心比喻贯穿全文就够，别每段换一个；
       - 金句全篇 1~2 句——不是每段都要有结论，其他段把事实说完就停；
       - 模具词（先说结论/算笔账/更少人注意/真正的/但前提/换句话说）全篇 ≤ 1 次；
       - 至少 1/3 的段落结尾不做总结；至少一半的小节不引入新数字；
       - 每篇至少 1 处**可直接验证的具体细节**（热评原话、官方演示的具体画面、模型回答的片段），
         必须真实可溯源——这是人味的合法来源，禁止用编造的个人经历代替。
   - 语气克制专业，少用感叹号；账号定位见下方「账号定位」小节。
   - **产物纪律**：草稿全文只写入 `article.txt` / `article.html` 文件，**绝不把全文或大段正文输出到对话回复里**；回复里只发第 8 步的简短通知。

4. **去 AI 味自查**（humanize-zh-pro 技能）：
   - 把初稿纯文本存为 `scripts/article.txt`，执行：
     `bash ../humanize-zh-pro/scripts/detect-ai-taste.sh scripts/article.txt`
   - **按维度读报告，不追总分**：只把维度1（结构套话）和维度4（连接词）当硬门槛，非 0 就按报告
     点名的短语改掉，归零即停手；维度3（人性化分）奖励 emoji/语气词/「我觉得」，与本账号的克制
     编辑口吻相反，**不要为了抬分去改**；维度1/4 归零后总分停在「中度AI味」是地板效应，属正常。
   - 改写**只动文风，不动事实、数字和引语**；全文重写不会改变未命中的维度，别烧第二轮。
   - 再跑风格层自查：`node scripts/check_style.mjs scripts/article.txt`。打印出的 ⚠️ 项按点名改——
     对仗超了就拆成散句，金句/总结超了就删掉几处总结，模具词超了就换说法。归零即停，别烧第二轮。

5. **排版**：把正文写成 WeChat 兼容 HTML，保存为 `scripts/article.html`。要求：
   - 只用 `<section>` `<p>` `<strong>` `<span>` `<blockquote>` `<table>` `<thead>` `<tbody>` `<tr>` `<th>` `<td>` `<ul>` `<li>` `<hr>` `<img>`，样式全部内联。
   - **主题色为亮橙色 #FF6622**：行内强调文字用 `#FF6622`；荧光高亮底色 `#FFE9DC`；
     引用块：左边条 `#FF6622`、底色 `#FFF4EC`。
   - 正文颜色 #333，字号 16px，行高 1.75，段间距 14px。**每个正文段落 `<p>` 都必须显式写
     `font-size:16px`，禁止只写在外层 section 上靠继承**（微信渲染器对继承不保证）。
   - **排版节奏（防文字墙）**：每段 ≤ 80 字（约 5 行），一段只讲一个要点；每 300 字左右插一个小标题；
     整篇强调色只用橙色系（≤2 种），分割线 ≤ 4 条，emoji ≤ 4 个且不连续。
   - **小节标题固定用「巨号编号 + 标题」模板**（开场与收尾段不编号，编号对应第 3 步的结构）：
     ```html
     <section style="margin:26px 0 14px;">
       <section style="font-size:56px;font-weight:bold;color:#FF6622;line-height:1;">01</section>
       <p style="margin:4px 0 0;font-size:18px;font-weight:bold;color:#333;">小节标题写成利益点</p>
       <section style="width:40px;height:4px;background:#FF6622;margin-top:8px;">&#8203;</section>
     </section>
     ```
   - **正文配图（每篇 0~3 张，按「图能不能替你说清一句话」判断，配不到就不配，不要硬凑）**：
     - **值得配**：模型卡/参数表、产品界面截图、架构或流程图、演示画面、关键对比图——图在传达文字讲不清的信息。
     - **不值得配**：纯装饰大图、发布会合影、与正文重复的图。
     - **来源只认官方**（官方博客 / docs / GitHub / 模型卡页面）。找图：
       `node scripts/fetch_og_image.mjs --url <官方页面地址>` 会打印该页 og:image 和正文前几张图片地址，挑最贴题的那张。
     - 拿到地址后上传换微信 CDN 再插（外链会被微信吞掉）：
       `node scripts/upload_image.mjs --url <图片地址>`（或 `--file 本地文件`），stdout 输出 CDN 地址。
     - 数字密集（≥3 个同维度数字）且官方没图时，用 `python3 scripts/gen_chart.py --data '<JSON>'` 自绘数据图。
     - 插入模板（**图注是硬要求**：官方图写「图源：xxx」，自绘图带「数据来源」）：
       ```html
       <section style="text-align:center;margin:16px 0;">
         <img src="{CDN地址}" style="width:100%;">
         <p style="margin:6px 0 0;font-size:12px;color:#999;">图源：OpenAI 官方博客</p>
       </section>
       ```
     - **可达性（实测，每个源最多试一次，别反复硬试）**：anthropic.com、github.com、arxiv.org 直连可达；
       openai.com 被 403、huggingface.co 超时、x.com / facebook / youtube / instagram 不可达——这些源的图
       要么跳过配图、要么用文字转述。
     - **兜底路径（主源不可达时，如 x.com / facebook 上的新闻）**：从 digest 里同题的国内媒体报道
       （量子位 / 爱范儿 / IT之家，用 fetch_og_image 逐个试）取**截图类图片**（对原帖的截图、产品界面截图）
       和厂商官方素材；**媒体自制的原创图表/信息图一律不取**——数据公开的用 gen_chart.py 自画。
       图注写全来源链：`图源：X@karpathy（via 量子位）`。脚本已过滤站点 logo/二维码/横幅。
     - 下载失败、超 10MB、格式不明就放弃配图。**禁止用文生图（Seedream）做正文插图**——封面专用。
   - 不用外链 CSS/JS；`<img>` 仅限微信 CDN 地址。
   - **强调卡片**（放核心洞察，替代把金句埋在正文里，每篇 ≤ 2 张）：
     ```html
     <section style="padding:8px 6px 12px;">
       <section style="background:#FFF4EC;border:1px solid #FF662233;border-radius:10px;padding:16px 20px;">
         <p style="font-size:15px;color:#333;line-height:1.9;margin:0;font-weight:500;">
           <span style="color:#FF6622;font-weight:700;">一句话：</span>核心洞察写在这里。
         </p>
       </section>
     </section>
     ```
   - **数据高亮卡**（单个关键数字砸进读者脑子时用；**只放短数值/短短语，≤12 字**——长句判断用强调卡片，
     不要塞进高亮卡，否则手机端折行很难看；卡片每篇 ≤ 1 张，数字必须真实）：
     ```html
     <section style="padding:8px 6px 12px;">
       <section style="background:linear-gradient(135deg,#FF6622,#E05516);border-radius:12px;padding:20px;text-align:center;">
         <p style="font-size:24px;font-weight:800;color:#fff;margin:0;line-height:1.3;">0.29 美元/次</p>
         <p style="font-size:14px;color:#ffffffcc;margin:8px 0 0;">数据说明：一句话讲清这个数字的含义</p>
       </section>
     </section>
     ```
     （主数字 24px 足够突出；不要用 36px 及以上——手机端会压过正文。）
   - **对比双栏**（谁受益谁受伤 / 新旧对比 / 正反两面，每篇 ≤ 2 组）：
     ```html
     <section style="padding:8px 6px 12px;">
       <section style="display:flex;gap:10px;">
         <section style="flex:1;background:#FFF4EC;border-radius:10px;padding:14px;text-align:center;">
           <p style="font-size:13px;color:#FF6622;font-weight:700;margin:0 0 6px;">受益方</p>
           <p style="font-size:14px;color:#333;margin:0;">谁、为什么</p>
         </section>
         <section style="flex:1;background:#f5f5f5;border-radius:10px;padding:14px;text-align:center;">
           <p style="font-size:13px;color:#666;font-weight:700;margin:0 0 6px;">受损方</p>
           <p style="font-size:14px;color:#333;margin:0;">谁、为什么</p>
         </section>
       </section>
     </section>
     ```
   - **表格**（多维对比，如 参数/价格/跑分对照）：外层包一段 `<section style="padding:0 12px;">`，
     让表格两侧各缩进 12px、比正文块略窄，避免通栏贴边的压迫感；表头底色 #FF6622 白字，
     表格本体 `width:100%;border-collapse:collapse`，单元格 `border:1px solid #ddd;padding:8px`，
     隔行浅灰 `background:#f7f7f7`，字号 13px。
   - **CSS 条形图**（同维度数值对比，如 各家价格/跑分），纯内联样式，微信兼容：
     每根条 = 一段 13px 灰色标签行（`名称 · 数值`）+ 一段外槽（`background:#efefef;height:18px;border-radius:3px`）
     内嵌一根按数值比例设 `width:xx%` 的彩条（本期主角用 #FF6622，对照项用 #bfbfbf，数值必须按真实比例）。
     形如：
     ```html
     <section style="margin:0 0 6px;">
       <p style="margin:0 0 2px;font-size:13px;color:#666;">DeepSeek 1017 版 · 每任务约 1.5 元</p>
       <section style="background:#efefef;height:18px;border-radius:3px;">
         <section style="background:#FF6622;width:2%;height:18px;border-radius:3px;">&#8203;</section>
       </section>
     </section>
     ```
     （内条里放 `&#8203;` 零宽字符防止空 section 被微信吞掉；条与条之间按最大值归一化。）
   - 文末固定三件套：
     ① 关注引导一行（如「每天一条 AI 热点解读，欢迎关注」——只做邀请，**严禁利诱和门槛**：
     不得出现「关注后领取/才能看/参与抽奖/送资料」这类把关注设为条件的文案，那是诱导关注，
     会被删文甚至封号；「转发才能看」类诱导分享同样禁止）；
     ② 话题标签另起一行（如 `#AI资讯 #大模型`，吃搜一搜和话题页的曝光）；
     ③ 小字一行：「本文由 AI 辅助整理生成，内容以官方来源为准。」

6. **生成封面**（文生图：如实画标题 + 短标签，画面要有商业杂志封面级质感）：

   **先拆标题，再画图**。四要素照旧拆——主体、关键数字、关系/动作、结论——画面必须全部覆盖：

   ```
   node scripts/gen_cover.mjs --topic "本期标题；一句话说清这篇讲什么" \
     --style "画面要点：A 与 B 的什么关系，并用构图/位置体现关键数字的含义" \
     --labels "Kimi 3万亿参数|Opus 5.5"
   ```

   - `--labels`：要印在画面上的短标签，用 `|` 分隔，**最多 2 个**（超过 2 个模型会丢字）。
     数字必须和主体组成短语（如「Kimi 3万亿参数」）；单独的数字实测会被漏画。
   - 画面要同时表现主体、关系和数字的含义，读者一眼能对上标题。
   - **视觉标准（平衡线）**：商业杂志封面级质感——主体大而突出、放在视觉中心、构图讲究；
     柔和的方向光与自然阴影、色彩鲜明且有一个主色调、背景简洁有层次。
     两个都要避开：不能平淡如记录照（没光影没层次），也不做超现实拼贴、乱堆元素和夸张特效。
   - 脚本调用文生图模型（火山 Ark Seedream）输出一张 1664x704（≈2.35:1）封面，
     stdout 打印封面路径，记为 `COVER_PATH`。
   - 生成失败时才兜底：从 `../../covers/` 里挑一张静态图（跳过上次用过的）。

7. **发布到草稿箱**：

   ```
   node scripts/mp_publish.mjs --title "文章标题" --html scripts/article.html --author "AGI虾说" \
     --cover "<COVER_PATH>" --digest "一句话判断式摘要（分享卡片、搜一搜结果都显示它；写最锋利的判断，不要复述新闻）"
   ```

   凭据在环境变量 `WECHAT_MP_APPID` / `WECHAT_MP_SECRET` / `ARK_API_KEY` 里（运行环境已配置），不要把凭据写进任何文件或输出。

   - **发布成功后归档**（每期必做，供后续热度分析）：
     `node scripts/archive_article.mjs --title "本期标题" --type <模型|产品|技术|应用|商业|政策> --slot <早报|晚报> --skeleton "<本期骨架>" --digest "本期摘要" --cover "<COVER_PATH>"`
     脚本自动读取 `scripts/article.txt` / `article.html`，写入 `archive/` 并在 `archive/index.jsonl`
     追加一条索引（含日期、题材、骨架、摘要、封面路径、阅读量占位）。

8. **汇报（简短通知制）**：向触发渠道只发一条简短通知，包含：本期标题、一句最想让读者记住或争论的判断
   （不要复述新闻）、一句提醒：到公众号后台「草稿箱」检查排版后**当天尽快发表**——每天只有 1 次「群发」会
   推送给粉丝，第二篇只能「发布」（不推送、阅读量会接近 0），挑更值得的那篇群发；发表时勾选「内容由 AI 生成」声明。
   不要把正文或链接列表发到对话——长内容只在草稿箱里，微信通知以「一声」为限。
   脚本报错时原样转述 errcode/errmsg 和脚本给出的提示，不要自己猜。

## 账号定位

- 公众号名称：AGI虾说
- **内容主线**：每天就**一条最热的 AI 新闻**写一篇自己的文章。热点范围（按优先级）——
  ① 新模型/重大版本发布；② 产品与开源生态重大更新；③ 技术或科研重大突破；
  ④ AI 落地应用：给生活带来什么变化、帮人提效的真实案例；
  ⑤ 国内大厂 AI 商业战局：财报、融资、烧钱、收入结构变化、战略攻防（**次选，硬配额**）。
  ⑤ 不是主线：只有当天完全没有 AI 新闻/产品/技术/应用类选题时才用；每 5 期最多 1 期，
  且不能连着两期；「素材特别好」不算理由——读者订阅的是「AI 发生了什么」，不是「AI 公司赚了多少钱」。
  同一个模型/同家公司别连出两期（换别的模型或技术新闻即可）；应用/商业类不能连续两期；
  **每 5 期至少 3 期是模型/产品发布或技术突破类**——这是账号的专业感来源。
- **文章形态**：单篇深度 + 自己的观点，不是新闻概要、不是多闻合辑。
- **面向读者**：关注 AI 的普通从业者和爱好者——想第一时间知道「出了什么、跟我有什么关系、怎么用起来」。
  不追求论文级深度，追求讲人话、可操作。
- **口吻偏好**：像懂行的朋友转述今天的大事——事实准确、判断直接、不端着；
  少形容词，多具体数字和细节；该给读者「怎么用」的提示就直说。
  风格对标：量子位的信息密度 + TLDR 的信源纪律，但判断比它们更直接。
- **视觉**：文章以亮橙色 (#FF6622) 为主题色；小节标题用巨号编号 01/02/03 + 橙色短线，固定模板（见第 5 步）；
  正文配图只用官方截图（标「图源」）和代码生成的数据图（标「数据来源」），禁止文生图做正文插图；
  封面走文生图：如实画标题的主体与关系 + 短标签标注主体和数字，商业杂志封面级质感，高级耐看、不夸张不平淡。
