# AI 资讯 → 单篇热点文章 → 公众号草稿

本技能目录记为 `SKILL_DIR`（就是本文件所在目录）。所有路径相对 `SKILL_DIR`。

## 执行步骤

1. **抓新闻**：`node scripts/fetch_news.mjs`，然后读 `scripts/digest.md`。
   个别源失败属于正常，忽略失败的源继续；如果所有源都失败，向触发渠道报告失败原因，不要硬写。

2. **定选题与角度**：从摘要里挑出**今天最热的一条**新闻，它是本文唯一主角：
   - 热度信号：多个源同时在报、HN 高分高评论、有官方公告或多方回应、读者会转发讨论的那种。
   - 类型范围按账号定位（见文末）：新模型发布、重大更新、重大突破、AI 落地应用/提效、
     国内大厂 AI 商业战局（见下条）。
   - **大厂商业战局类（用户验证过的爆款模式，权重最高）**：财报数字、烧钱投入、收入结构变化、
     战略转向、巨头与国产的攻防——大厂用真金白银投的票比发布会诚实。写法抓反差：
     越成功越焦虑（豆包越火字节越慌）、越亏越下注（净利跌 70% 再烧 5000 亿）、巨头成了国产慌了
     （Copilot 做成，WPS 渡劫）、增长背后藏着转型（联想最值钱的业务不是 PC）。
   - **差异化硬门槛**（跟全网 AI 号撞车的解法，每期必过）：
     - 列 2~3 个候选主角，逐个自问：「今晚其他 AI 号大概率会怎么写它？」——它们都会写的角度就是禁区。
     - 人人都在写的热点，只有拿到别人不会写的角度才选；拿不到就换次热但**跟读者的钱、时间、饭碗
       直接相关**的题——读者利益权重高于热度。
     - 类型别扎堆：模型发布/价格跑分类连出两期后，下一期主动换落地应用、真实案例或争议话题。
     - 角度必须从下面挑一个，不从「事件本身」出发：
       ① 算一笔别人没算的账（成本/时间/风险）；② 谁受益谁受伤；③ 上手实测（别人转述，我们动手）；
       ④ 反共识判断（都说好我挑毛病，都在慌我说不慌）；⑤ 中文语境翻译（这事对国内读者到底意味着什么）。
   - 定了主角后，围绕它用 web_search 补素材：官方公告、技术细节、各方反应、相关数据（全文最多搜 5 次，当前走 Tavily）。
     **搜索额度自愈**：web_search 若报额度类错误（429 / usage limit / quota exceeded），执行
     `openclaw config set tools.web.search.provider brave` 切到 Brave 并重试；平时不要动这个配置。
   - 事实必须可溯源，禁止编造摘要和搜索结果里没有的数字、引语。
   - 当天没有特别突出的热点时，选信息量最大的一条深挖，**不要写成多闻合辑**。

3. **写作**（中文，800~1500 字，目标：**一篇有自己观点的单篇评论文章，像真人编辑写的，不是通稿复述**）：
   - 标题 ≤ 45 字（双句转折式可写满；单句尽量 ≤ 30），目标：**读者在信息流里划过去 1 秒就想点**。
     实体打底（点清主角是谁）+ 钩子加码，钩子从下面挑 1~2 个组合，不贪多：
     ① 对抗冲突：确有对比数据时敢点名对手（「绝杀OpenAI」）；
     ② 拟人场景：把模型当人写（「上岗」「替你打工」「抢饭碗」）；
     ③ 具体数字：价格/时长/倍数（「24小时」「一个任务一块五」），好过「价格再创新低」；
     ④ 利益代入：直接写跟读者的关系（「替你」）；
     ⑤ 强转折骨相（大厂商业类首选）：两句对照各带一个具体数字——投入大却失灵、增长猛却藏转型、
       越成功越焦虑、越亏越下注；公司可以当人写命运（「慌了」「渡劫」「下注」）。
     金额数字必须配参照系（「一季度赚 330 亿，秒了整个科创板一年的利润」），光秃秃的金额不如有对比的金额。
     正文写完后**强制产出 3 个不同钩子的候选标题**自比，选信息流里最想点的那个；
     允许最多一个感叹号，只放在钩子处，不连用标点。
     吸睛的底线是事实：不编造排行宣称、金额、时间词、权威背书；「绝杀/吊打」级强度词必须有真实对比
     数据撑腰，撑不住就降级为可证实的说法。
   - 参考结构（按内容灵活调整，不硬套）：
     开头别只复述通稿（「X月X日，Y发布了Z」读者早刷到过了）：第一段就要出现别人没有的东西——
     判断、账或场景，回答「别处也有这条新闻，凭什么读你这篇」→ 讲清楚发生了什么（事实、数字、多方说法）→
     为什么重要，你的分析与判断 → 跟读者有什么关系、怎么用起来 → 抛一个真问题收尾（见互动设计）。
   - **借来的好手艺**（研究量子位/TLDR/The Rundown 后的结论）：
     - 事实段三句式：是什么 → 核心数据/对比 → 价格与获取渠道，能三句说完不写五句。
     - 断言挂信源：厂商的宣称写「官方称/其表示」，自己的判断才用「我」——两类声音必须分开，这是可信度的来源。
     - 关键段结尾带一句「这意味着什么」：不停留在转述，用一句话点出赌注或待验证的问题。
     - 「怎么用」给具体动作：入口、命令、prompt、价格，读者能直接复制照做。
     - 对「颠覆/史诗级/一夜变天」式宣称保持警惕：先查证据，多数真正的变化比宣传小一号。
     - 评论的底气来自动手：有条件就实测（跑一个最小例子、查官方文档），没条件就明说依据，**不装亲测**——「我先做过了，所以不必喊」。
     - 人味来自判断、节奏和具体细节，**不靠编造个人经历或生活场景**（AI 没有生活，编了就是假新闻）。
   - **要有「自己的东西」**：观点、判断、延伸、类比、算一笔账都可以；把几段通稿拼起来不算写完。
   - **互动设计（每篇必做，目标：看完、留言、转发各占一个钩子）**：
     - 结尾抛一个**具体的、可站队的争论问题**，禁止「你怎么看」这种空问；要问「你的邮箱敢交给它管吗」
       「这个价你会换吗」这种一句话能答、且答案明显分两派的。
     - 争议点在文中要有正反两方，只写一方的文章没人留言。
     - 全文至少一句敢下判断的结论句，写到值得截图转发的程度。转发测试：读者转出去是在向同行表达什么
       （「我比同行先知道」/「我看得更准」/「我早说过」）？给不出这句话，就回去把判断写锋利再收尾。
   - **数字可视化（仅在必要时，不是每篇都要）**：当某段数字密集（≥3 个同维度数字、或量级差悬殊的对比）时，
     用表格或 CSS 条形图把数字「画」出来，正文只留结论（见第 5 步模板）；
     散落的一两个数字直接写在句子里就好，别硬画。数据必须与来源一致，不得为视觉效果歪曲比例。
   - **去 AI 味硬规则**（初稿就要遵守，别指望事后补救）：
     - 禁用词：随着、值得注意的是、总而言之、综上所述、赋能、闭环、助力、不仅…更是、在这个…的时代、引人注目、让我们、可以说、毫无疑问、拭目以待、未来已来。
     - 不用「首先/其次/最后」「一方面/另一方面」的机械结构；不用三句式排比堆砌。
     - 长短句交错，一段不超过三句，多用短句；开头一句直接说事，不铺垫宏大背景。
     - 点评要有具体立场，敢下判断；引用具体数字和细节，不写放之四海皆准的空话。
     - 像编辑跟读者聊天：可以少量用口语衔接（如「这事」「说白了」「好消息是」），全篇不超过 5 处。
   - 语气克制专业，少用感叹号；账号定位见下方「账号定位」小节。
   - **产物纪律**：草稿全文只写入 `article.txt` / `article.html` 文件，**绝不把全文或大段正文输出到对话回复里**；回复里只发第 8 步的简短通知。

4. **去 AI 味自查**（humanize-zh-pro 技能）：
   - 把初稿纯文本存为 `scripts/article.txt`，执行：
     `bash ../humanize-zh-pro/scripts/detect-ai-taste.sh scripts/article.txt`
   - **按维度读报告，不追总分**：只把维度1（结构套话）和维度4（连接词）当硬门槛，非 0 就按报告
     点名的短语改掉，归零即停手；维度3（人性化分）奖励 emoji/语气词/「我觉得」，与本账号的克制
     编辑口吻相反，**不要为了抬分去改**；维度1/4 归零后总分停在「中度AI味」是地板效应，属正常。
   - 改写**只动文风，不动事实、数字和引语**；全文重写不会改变未命中的维度，别烧第二轮。

5. **排版**：把正文写成 WeChat 兼容 HTML，保存为 `scripts/article.html`。要求：
   - 只用 `<section>` `<p>` `<strong>` `<span>` `<blockquote>` `<table>` `<thead>` `<tbody>` `<tr>` `<th>` `<td>` `<ul>` `<li>` `<hr>`，样式全部内联。
   - **主题色为亮橙色 #FF6622**：
     - 小标题加粗并带左侧强调条：`border-left:4px solid #FF6622`，文字同色 `#FF6622`，17px。
     - 行内主题色强调文字也用 `#FF6622`；荧光高亮底色 `#FFE9DC`。
     - 引用块：左边条 `#FF6622`、底色 `#FFF4EC`。
   - 正文颜色 #333，字号 15px，行高 1.75，段间距 12px。
   - 不用外链 CSS/JS；不放 `<img>`（封面由发布脚本单独传，正文配图仅在有微信素材外链 URL 时允许）。
   - **表格**（多维对比，如 参数/价格/跑分对照）：外层包一段 `<section style="padding:0 12px;">`，
     让表格两侧各缩进 12px、比正文块略窄，避免通栏贴边的压迫感；表头底色 #FF6622 白字，
     表格本体 `width:100%;border-collapse:collapse`，单元格 `border:1px solid #ddd;padding:8px`，
     隔行浅灰 `background:#f7f7f7`，字号 13px。
   - **CSS 条形图**（同维度数值对比，如 各家价格/跑分），纯内联样式，微信兼容：
     每根条 = 一段 13px 灰色标签行（`名称 · 数值`）+ 一段外槽（`background:#efefef;height:18px;border-radius:3px`）
     内嵌一根按数值比例设 `width:xx%` 的彩条（本期主角用 #FF6622，对照项用 #bfbfbf，数值必须按真实比例）。
     形如：
     ```html
     <section style="margin:0 0 6px;">
       <p style="margin:0 0 2px;font-size:13px;color:#666;">DeepSeek 1017 版 · 每任务约 1.5 元</p>
       <section style="background:#efefef;height:18px;border-radius:3px;">
         <section style="background:#FF6622;width:2%;height:18px;border-radius:3px;">&#8203;</section>
       </section>
     </section>
     ```
     （内条里放 `&#8203;` 零宽字符防止空 section 被微信吞掉；条与条之间按最大值归一化。）
   - 文末固定加一行小字：「本文由 AI 辅助整理生成，内容以官方来源为准。」

6. **生成封面**（每期实时生成，画面**只跟本期主题有关，不限定颜色**）：

   ```
   node scripts/gen_cover.mjs --topic "本期标题；一句话说清这篇讲什么" --style "画面冲突点（谁对谁/什么在变化，如：两大AI巨头棋盘对弈、机械臂坐进办公工位）"
   ```

   封面按**信息流缩略图**标准做：读者刷到时 1 秒被抓住——戏剧张力、动感构图、高对比光影、主体大而突出，
   拒绝平淡的「科技感底图」。脚本调用文生图模型（火山 Ark Seedream）输出一张 1664x704（≈2.35:1）封面，
   stdout 打印封面文件路径，把它记为 `COVER_PATH`。
   生成失败时才兜底：从 `../../covers/` 里挑一张静态图（跳过上次用过的）。

7. **发布到草稿箱**：

   ```
   node scripts/mp_publish.mjs --title "文章标题" --html scripts/article.html --author "AGI虾说" --cover "<COVER_PATH>"
   ```

   凭据在环境变量 `WECHAT_MP_APPID` / `WECHAT_MP_SECRET` / `ARK_API_KEY` 里（运行环境已配置），不要把凭据写进任何文件或输出。

8. **汇报（简短通知制）**：向触发渠道只发一条简短通知，包含：本期标题、一句最想让读者记住或争论的判断
   （不要复述新闻）、一句提醒（到公众号后台「草稿箱」检查排版后手动发表，勾选「内容由 AI 生成」声明）。
   不要把正文或链接列表发到对话——长内容只在草稿箱里，微信通知以「一声」为限。
   脚本报错时原样转述 errcode/errmsg 和脚本给出的提示，不要自己猜。

## 账号定位

- 公众号名称：AGI虾说
- **内容主线**：每天就**一条最热的 AI 新闻**写一篇自己的文章。热点范围——
  ① 新模型/重大版本发布；② 产品与开源生态重大更新；③ 技术或科研重大突破；
  ④ AI 落地应用：给生活带来什么变化、帮人提效的真实案例；
  ⑤ 国内大厂 AI 商业战局：财报、烧钱、收入结构变化、战略攻防。
  纯行业融资/政策只在特别重大时才当主角；但大厂财报/烧钱/战略转向是主推类型。
  配比自觉：每天两期里至少一期优先从⑤里挑（素材合格时）；模型发布/价格跑分类连出两期必须换型——
  读者要的是「跟我有什么关系」，不是跑分日历。
- **文章形态**：单篇深度 + 自己的观点，不是新闻概要、不是多闻合辑。
- **面向读者**：关注 AI 的普通从业者和爱好者——想第一时间知道「出了什么、跟我有什么关系、怎么用起来」。
  不追求论文级深度，追求讲人话、可操作。
- **口吻偏好**：像懂行的朋友转述今天的大事——事实准确、判断直接、不端着；
  少形容词，多具体数字和细节；该给读者「怎么用」的提示就直说。
  风格对标：量子位的信息密度 + TLDR 的信源纪律，但判断比它们更直接。
- **视觉**：文章以亮橙色 (#FF6622) 为主题色；封面走「信息流缩略图」路线——戏剧张力、高对比光影、
  动感构图，贴合当期主题，一眼抓人；拒绝平淡留白底图。
